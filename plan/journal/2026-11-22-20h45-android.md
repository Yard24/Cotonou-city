# 22 novembre 2026, 20h45 — version Android (branche `android`)

Demande de Bravo : version Android installable (.apk), jouable au doigt sur un téléphone d'entrée de gamme, fabriquée par GitHub Actions à côté du .exe, sans rien changer pour Windows. Décisions notées dans `docs/decisions.md` (section du 22 novembre).

## Fait et vérifié
- Commandes tactiles (`scripts/tactile.gd`) : manette virtuelle à gauche, boutons à droite qui n'apparaissent que quand ils servent, Pause toujours visible, plusieurs doigts, textes qui citent les boutons au lieu des touches, onglet « Tactile » dans les options (forcer sur PC, taille, opacité). Les boutons appuient sur les mêmes actions d'entrée que le clavier.
- Android : bouton Retour = Échap ; arrière-plan = pause et sauvegarde automatique ; zone sûre (encoche) ; paysage imposé ; niveau graphique Bas par défaut ; image 3D sur 540 lignes au plus au niveau Bas ; décor fixe regroupé sur téléphone (`scripts/fusion.gd`, 1 133 blocs en 56 morceaux, image identique au pixel près sur une capture de comparaison).
- `project.godot` : `quit_on_go_back=false`, orientation paysage (capteur), compression ETC2/ASTC, ombres 2048 sur téléphone.
- `export_presets.cfg` : préréglage « Android » (com.yard24.marinacity, arm64-v8a et armeabi-v7a, sans Gradle, icônes, aucune clé). Le préréglage Windows exclut `icones/`.
- Icône provisoire originale (`icones/`, dessinée par `icones/dessiner_icone.py`).
- GitHub Actions : tâche `android` (Java 17, outils Android, Godot 4.3, clé de test gardée dans le cache, fabrication, vérification par `.github/verifier_apk.sh`, fichier « MarinaCity-Android »). La tâche Windows refuse désormais toute ligne `SCRIPT ERROR`.
- Test automatique : `scripts/selftest_tactile.gd` (faux touchers, six écrans simulés, textes, manette, deux doigts, boutons utiles, menus, Retour, arrière-plan, décor regroupé, puis quelques secondes de vrai jeu au doigt). `SELFTEST OK`, aucune ligne `SCRIPT ERROR`.
- `selftest_menus.gd` : les rangs des réglages comptent maintenant les onglets (un cinquième onglet a été ajouté) au lieu de supposer 4.
- Documents : `docs/android.md`, `docs/systemes/commandes_tactiles.md`, `docs/conventions.md` (section Android), `docs/systemes/menus.md`, README, `TRAVAIL_AUTOMATIQUE.md`.

- .apk fabriqué ici (outils Android des paquets Ubuntu, les serveurs de Google étant bloqués) puis par GitHub Actions ; contenu vérifié : paquet, nom, Android 5.0 minimum, cible 34, moteur pour les deux processeurs, signature v1, v2 et v3, orientation paysage.
- Captures d'écran (rendu logiciel sous Xvfb) à 1280 × 720 et 1600 × 720 : à pied, à moto, pause, accueil, options.

## Non vérifié (aucun téléphone ici)
Lancement réel, fluidité, confort au doigt, encoche réelle, bouton Retour réel, mise en arrière-plan réelle. Les images par seconde des captures (12 à 19) viennent d'un rendu logiciel sans carte graphique : elles ne disent rien du téléphone.

## Choix et remarques
- `plan/taches.csv` non modifié : aucune tâche Android n'y figure ; le travail est décrit ici et dans `docs/decisions.md`.
- Un appui simulé par `Input.action_press` est vu « tout neuf » à l'image suivante (règle de Godot 4.3) : le test synchrone vérifie l'état appuyé, la partie « vrai jeu » vérifie l'effet.
- `Input.parse_input_event` n'arrive pas jusqu'aux nœuds en mode sans écran : les faux touchers sont donnés directement à `tactile.traiter()`, qui est aussi ce qu'appelle `_input()`.
- Les véhicules et passants ne sont pas regroupés (ils bougent) : c'est le prochain levier si le téléphone est lent.
